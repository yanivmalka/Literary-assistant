                     EXTRACTION DIAGNOSTIC PACKAGE
════════════════════════════════════════════════════════════════════════════════

PURPOSE
───────
Diagnose why ability extraction is failing by analyzing raw Gemini API responses.

KEY QUESTION: Is Gemini returning empty arrays, or is the response being lost?

THREE HYPOTHESES TESTED
───────────────────────
A) EMPTY ARRAYS - Gemini isn't extracting abilities even though prompted
B) PARSE FAILURES - Gemini extracts but response gets corrupted during parsing
C) WRONG FORMAT - Response structure doesn't match what code expects

════════════════════════════════════════════════════════════════════════════════
QUICK START
════════════════════════════════════════════════════════════════════════════════

1. Run extraction via web app (http://localhost:5173)
   - Create project
   - Upload document
   - Click Extract

2. Run diagnostic
   node diagnostic_extraction_analysis.mjs

3. Read results (especially DIAGNOSTIC SUMMARY section)

4. Follow recommendations

DIAGNOSTIC WORKFLOW
════════════════════════════════════════════════════════════════════════════════

1. CHECK EXISTING DATA
   What: Do we have extractions in the database?
   How: diagnostic shows "Found N extraction(s)"
   If yes: Continue to step 2
   If no: Run extraction via web app first

2. FETCH RAW RESPONSES
   What: Get the last 3 Gemini responses from database
   How: diagnostic_extraction_analysis.mjs fetches from raw_extractions table
   View: Terminal output shows response structure

3. ANALYZE STRUCTURE
   What: Is the JSON formatted correctly?
   How: Check top-level keys, array types, field names
   View: Shows "Keys: characters, abilities, magic_abilities..."

4. TEST HYPOTHESES
   What: Which scenario explains what we see?
   How: Three hypothesis checks (A, B, C)
   View: "DIAGNOSTIC SUMMARY" section clearly states which is confirmed

5. GET RECOMMENDATIONS
   What: What to fix based on the diagnosis?
   How: Diagnostic generates specific action items
   View: "RECOMMENDATIONS" section with exact next steps

6. TAKE ACTION
   What: Fix the identified issue
   How: Follow recommendations (check prompt, check parsing, check schema)
   View: After fix, rerun diagnostic to verify

  Check: Is response valid JSON?

  File: supabase/functions/extract-knowledge/index.ts

TROUBLESHOOTING
════════════════════════════════════════════════════════════════════════════════

Q: "No extractions found in raw_extractions table"
A: Run extraction via web app first (Create project → Upload doc → Extract)

Q: "Invalid API key"
A: Script uses hardcoded anon key. If failing, check Supabase connection

Q: "No projects found"
A: Create a project via web app before running extraction

Q: "raw_response is NULL"
A: Extraction failed. Check server logs or browser network tab

Q: What if I can't run Node.js?
A: Use DIAGNOSTIC_SQL_QUERIES.sql in Supabase SQL Editor instead

Q: How do I save the diagnostic output?
A: Diagnostic automatically saves JSON report:
   diagnostic_extraction_report_YYYY-MM-DD-HH-MM-SS.json
